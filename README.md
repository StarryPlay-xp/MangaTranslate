# 漫译（MangaTranslate）

自用的 iPhone / iPad App：在 App 内置的浏览器里看日漫、韩漫网页，先用 Apple Vision 在设备上找出文字，再交给大模型看图翻译成简体中文，最后把译文贴回原来的位置。大模型服务可以自己配置：默认是 DeepSeek，也能换成其他 OpenAI 兼容或 Anthropic 格式的服务，或者局域网里自己部署的模型。

## 目录结构

- `MangaTranslate.xcodeproj`、`MangaTranslate/`：iOS App
- `Packages/MangaCore/`：App 和验证工具共用的核心逻辑（文字识别、合并文字块、编号图、大模型翻译）
- `Config/Info.plist`：Info.plist 里写不进项目设置的部分（允许用 http:// 访问局域网、iPad 上只开一个窗口），编译时自动合并
- `Tools/OCRProbe/`：Mac 上的识别与翻译验证工具，用法见它的 README
- `samples/`：验证用的截图，不提交到仓库

## 在模拟器里运行

1. 用 Xcode 打开 `MangaTranslate.xcodeproj`
2. 窗口顶部选择 `MangaTranslate` 和一台 iPhone 或 iPad 模拟器，按 ⌘R 运行
3. 首页点"内置示例页"。在设置里打开"试运行"，可以不联网先检查识别和贴字效果

## 装到自己的 iPhone 或 iPad（免费 Apple ID）

1. Xcode → Settings → Accounts，添加自己的 Apple ID
2. 在左侧选中项目 → TARGETS 里的 `MangaTranslate` → Signing & Capabilities，Team 选自己的 Personal Team。如果提示 Bundle Identifier 已被占用，改成一个别人不会用的名字
3. 用数据线连接 iPhone 或 iPad，在 Xcode 顶部选择这台设备，按 ⌘R 运行
4. 第一次安装需要在设备上操作：设置 → 隐私与安全性 → 打开"开发者模式"并重启；然后在 设置 → 通用 → VPN 与设备管理 里信任自己的开发者证书
5. 免费签名 7 天后失效，到时连上 Mac 再运行一次就行，App 里的数据一般不会丢

选好 Team 后，项目文件里会多出一行 `DEVELOPMENT_TEAM`。这是开发者团队编号，不是密钥，提交到仓库没有问题。

iPad 上的区别：
- 支持横屏、竖屏和随意调整窗口大小（iPhone 上仍只支持竖屏）。横屏时一屏一页、两页并排的阅读器都能自动翻译
- 只能开一个窗口，开多个窗口会成倍发翻译请求
- 网页固定按手机版打开。iPad 上的 Safari 默认打开电脑版网页，所以同一个网站在漫译里的版式可能和 Safari 里不一样

## 使用方法

1. 首页右上角进入设置，在"模型服务"里点 DeepSeek 的"编辑"，粘贴 API Key 后点"保存"。Key 只保存在这台设备的钥匙串里。想换别的模型，见下面的"模型服务"
2. 在首页的气泡地址栏里输入漫画网址（输入的不是网址时用 Google 搜索），打开后在底部"更多"菜单里选好原文语言（日语或韩语）
3. 正常往下看就行：自动翻译默认开启，会翻译屏幕上和下方 3 屏以内的漫画图片。左右翻页的阅读器会提前翻网站已经加载好的前后各约 3 页（只翻和当前页一样大的图，广告页、推荐位不翻），翻过去时通常已经翻好。往下滑时上下工具栏会自动收起，往上滑就会出现
4. 底部中间的"译"字气泡是自动翻译开关，品红色表示开启；正在翻译时，气泡轮廓上有一圈白色虚线在流动。某张图翻译超过 0.6 秒时，图片右上角会出现一个小小的三个点。译文是模型边写边返回的，一页里的气泡会一处处陆续出现；条漫的长图会切成几段同时翻。三个点等整张翻完才消失
5. 点一下译文可以临时看原文，再点一下恢复。文字周围是纯色（白气泡、黑底说明框、纯色块）时，用同样的颜色盖住原文再写中文，看起来就像直接换了字，拟声词和标题也一样；周围是画面时，拟声词和封面标题、宣传语这类大字显示成原文左上角的半透明小标签，不挡画面，对白和旁白仍用白底盖住。手绘的拟声词 Apple Vision 识别不出来，暂时不会翻译
6. 想看懂网页上的日文、韩文（菜单、作品名、简介、评论），在"更多"菜单里打开"翻译网页文字"：网页上的文字会原地换成中文，之后打开的网页和往下滑新加载出来的文字也会自动翻译，App 重启后保持开启。再点一次关掉，网页马上恢复原文。只翻译屏幕上方半屏到下方 2 屏以内的文字，滑到哪翻到哪；同样的文字（比如各页都有的菜单）有缓存，不会重复花钱
7. 顶栏中间是地址栏，显示网页标题和网址：点一下可以改网址或输入关键词搜索，长按可以复制网址。顶栏的星标把当前页面加入书架；"更多"菜单里还有"只翻译这一屏"、清除译文、刷新和设置

首页的"漫画网站"收录了常见的韩漫、日漫正版平台（点右侧切换韩漫/日漫，左右滑动查看），点一下直接打开，并把原文语言切到对应的韩语或日语。免费章节、付费、年龄验证和地区限制以各网站为准。

首页的"继续看"会记住上次看的页面，点开后回到上次看到的位置；书架显示每个书签的页面缩略图。

翻译过的图片会按模型服务分别缓存译文，重看时直接显示，不再调用模型；换了模型会重新翻译，切回原来的模型时直接用缓存。人名等专有名词的译法按网站记住，下一话继续沿用。缓存和术语记忆都可以在设置里清除。

翻译时，漫画图片（带编号框）和识别出的文字会发送到你配置的地址。关掉"把图片发给模型"时只发文字。打开阅读页时，如果自动翻译开着，App 会先向这个地址发一个不带 Key、不带内容的连接请求，提前完成握手，让第一张图更快发出去。开启"翻译网页文字"时，网页上屏幕附近的日文、韩文文字会发送到你配置的地址。

## 模型服务

设置里可以保存多个模型服务，点一项就设为当前使用，方便换着用、比较译文。每个服务包括：

- **接口格式**：DeepSeek、Ollama、LM Studio、vLLM 等大多数服务用"OpenAI 兼容"（Chat Completions）；Claude 和兼容 Anthropic 的服务选"Anthropic"（Messages）
- **请求地址**：带不带 `/v1`、结尾有没有斜杠都行，编辑页会显示实际发送的完整地址，例如 `https://api.deepseek.com` → `https://api.deepseek.com/v1/chat/completions`
- **模型名**、**API Key**（可以不填，本地服务一般不需要；每个服务的 Key 分开存在钥匙串里）
- **支持看图**：模型不能看图就关掉，只发识别出的文字
- **JSON 模式**：OpenAI 兼容格式下要求模型只输出 json。有的模型不支持会报错，关掉后 App 也能从普通回复（包括 ```json 代码块）里提取译文
- **最长等待**：本地小模型慢，可以设到 5 或 10 分钟

编辑页的"测试连接"只发一条很短的文字请求，用来确认地址、模型和 Key 能用。

费用：目前只有 DeepSeek 的 `deepseek-flash` 有价格数据，会估算费用；其他服务只显示 token 数。DeepSeek 专用的关闭思考参数也只发给 DeepSeek。

设置里的"DeepSeek 用量"显示今天、本月、上月和累计的调用次数、token 数和估算费用（美元）：

- 每次调用都按当时的单价计：工作日北京时间 9–12 点和 14–18 点是高峰时段，单价翻倍
- 回复格式不对、重试的那几次也花了钱，同样计入；"测试连接"也计入
- 只统计这台设备发出的调用，实际扣费以 DeepSeek 后台账单为准
- 账本只存每天的合计，不存请求内容，最多保留 400 天，可以在设置里清除

从旧版升级时，原来填的 DeepSeek Key 会自动搬到内置的 DeepSeek 配置里，不用重填。

### 用局域网里自己部署的模型

1. 在电脑上启动模型服务，并允许局域网访问。例如 Ollama 要设置环境变量 `OLLAMA_HOST=0.0.0.0`；LM Studio 要在本地服务器的设置里打开局域网访问
2. 查电脑的局域网 IP（Mac：系统设置 → Wi-Fi → 详细信息），手机和电脑连同一个 Wi-Fi
3. 在 App 里添加"OpenAI 兼容格式"的服务，地址填 `http://电脑IP:端口`（Ollama 默认 11434，LM Studio 1234，vLLM 8000），模型名填服务里的模型名。看不了图的模型记得关掉"支持看图"
4. 第一次连接时系统会询问是否允许漫译访问本地网络，选"允许"。以后可以在 iPhone 设置 → 隐私与安全性 → 本地网络 里修改

App 只允许对局域网地址（私有 IP、`.local`、`localhost`）用 `http://`，其他地址必须用 `https://`。局域网服务一次只发一个请求，免得小模型排队超时；云端服务同时最多发 4 个（长图的几段、相邻几张图一起翻）。

云端服务的某个请求发出 4 秒还没开始返回文字时，App 会再发一份同样的请求，哪份先开始返回就用哪份，另一份马上取消（局域网服务不这样做）。这种情况不常见，多发的那份如果服务端已经开始处理，可能照样计费，但不会记进设置里的用量统计。服务不支持边写边返回（流式）时，App 会自动改用普通请求。

## 查看翻译耗时

自动翻译每翻完一张图，会在系统日志里记一行各环节的耗时，用来找出慢在哪里。日志只有数字，没有图片地址和文字内容。

- 用 Xcode 把 App 装到手机上运行时：Xcode 底部的调试输出里直接能看到，在右下角的筛选框输入 `timing`
- 不经过 Xcode 时：用数据线把 iPhone 连上 Mac，打开 Mac 自带的"控制台"App，左侧选中这台 iPhone，点"开始"，搜索框输入 `category:timing`

一行汇总大致是这样（数字是示例）：

```text
图片 3（1426×2048）从发现到贴完 3.40 秒：排队 0.00 秒，下载 0.00 秒，识别 0.80 秒（1 段），模型 1 次，平均 2.55 秒，最慢 2.55 秒，等名额最长 0.00 秒，首字最快 1.20 秒，第一处译文 2.35 秒；贴了 9 处
```

- **从发现到贴完**：从网页报上这张图到译文贴好。canvas 页在翻页动画停下约 0.15 秒后才算"发现"
- **排队**：前面的图占着位置时要等多久
- **截图 / 下载**：canvas 页截取屏幕的时间，普通图片下载并解码的时间
- **识别**：手机上用 Vision 找文字、画编号图的时间，长图是各段加起来
- **模型**：从发出请求到收到完整回复，包括上传图片、模型生成和失败重试；另有一行写着首字时间、第几次成功和输入、输出 token 数
- **首字最快**：从发出请求到收到模型返回的第一个字。写着“靠对冲”的，是第一份请求太慢、第二份先返回了
- **等名额**：同时在翻的请求太多时，这一段排队等了多久
- **第一处译文**：从网页报上这张图到第一处译文贴出来，这是实际等待的感受

## 当前版本的限制

- 漫画画在 canvas 上的网站（比如マガポケ），要等这一页完整停在屏幕上才截图翻译，不能提前翻；被切块打乱后再拼起来的网站，需要用"只翻译这一屏"
- 只翻译已经加载好的图片；快速滑过去的图不会翻译，滑回来时会补上
- 网页文字翻译只处理主页面，嵌在 iframe 里的内容（比如部分评论区）不会翻译；一段文字被拆在几个标签里（比如中间夹着加粗）时会分开翻译，个别地方语序可能不够顺
- 翻译失败的图不会自动重试；清除译文后重新打开自动翻译即可重试
- 放在内嵌框架里的图片不会被翻译
- 只在模拟服务上验证过 OpenAI 兼容和 Anthropic 两种格式，还没有接真实的本地模型和其他服务商测试
